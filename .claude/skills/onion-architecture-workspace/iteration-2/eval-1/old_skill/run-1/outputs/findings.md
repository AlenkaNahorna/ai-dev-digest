# Onion Architecture Violations — labels module

1. **server/src/modules/labels/domain/label-policy.ts**: Imports `drizzle-orm` (`import { eq } from 'drizzle-orm';`), a forbidden dependency for the domain layer, which must contain pure business rules with no database/SDK imports.
2. **server/src/modules/labels/domain/label-policy.ts**: Imports `server/src/db/schema.js` (`import { labels } from '../../../db/schema.js';`), pulling a concrete persistence schema into the domain layer, which must stay free of database and infrastructure dependencies.
3. **server/src/modules/labels/adapters/inbound/http/labels.routes.ts**: Imports `drizzle-orm` directly (`import { eq } from 'drizzle-orm';`), which is an explicitly forbidden pattern for route/inbound-adapter files.
4. **server/src/modules/labels/adapters/inbound/http/labels.routes.ts**: The GET handler runs `db.select().from(labels).where(eq(labels.repoId, repoId))` directly against `db`/`labels` from `src/db/client.js` and `src/db/schema.js`, bypassing the application use-case and outbound persistence layers entirely instead of calling through a port/repository.
5. **server/src/modules/labels/adapters/inbound/http/labels.routes.ts**: The POST handler reads a `repository: LabelRepositoryPort` object out of the raw HTTP request body (`const body = request.body as { ...; repository: LabelRepositoryPort }`) and uses it to construct the use case, meaning persistence wiring is driven by untrusted transport input instead of being assembled in the composition root.
6. **server/src/modules/labels/domain/label-policy.ts**: Exports `labelsTableRef` (a Drizzle table reference) and `byId` (a Drizzle query-builder helper) from the domain module, leaking persistence-layer constructs into what must be pure domain rules/value objects.
7. **server/src/modules/labels/index.ts**: The module wiring never constructs `createLabelRepository()` from the outbound persistence adapter or registers it with the use case; the composition root fails to assemble the concrete repository implementation, leaving that responsibility to be improperly satisfied per-request in the HTTP adapter instead.
