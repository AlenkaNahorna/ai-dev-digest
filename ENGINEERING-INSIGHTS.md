# Engineering insights

Cross-cutting, actionable learnings that apply across modules. Keep entries append-only, specific, and evidence-backed. Module-specific details belong in the relevant module `INSIGHTS.md` file.

- [2026-09-27] **UI correctness**: Model relationship state and activation state separately. A resource can be linked/attached while disabled; controls must render `checked` from the activation field, not from the existence of the relationship. Evidence: `client/src/app/agents/[id]/_components/AgentEditor/_components/SkillsTab/SkillsTab.tsx:18-21`.
- [2026-09-27] **Async UX**: Every user-triggered mutation needs visible pending and error states. Without `Saving…`/disabled handling and an inline error, a failed or slow request is indistinguishable from a frozen button. Evidence: `client/src/app/skills/page.tsx:34`.
- [2026-09-27] **Design verification**: Treat every interactive element shown in a design as an acceptance criterion, not just a visual requirement. For each toggle, save action, tab, and version-row action, verify click behavior, persistence after reload, and the error path. Evidence: `client/src/app/agents/[id]/_components/AgentEditor/_components/SkillsTab/SkillsTab.tsx:21` and `client/src/app/skills/page.tsx:32-34`.
- [2026-09-27] **Version history**: A version list is incomplete when the design exposes comparison behavior. Version history should provide a deterministic diff between adjacent immutable snapshots and must never execute imported or stored markdown. Evidence: `client/src/app/skills/page.tsx:32` and `server/src/modules/skills/adapters/outbound/persistence/repository.ts:39-42`.
- [2026-09-27] **Database integrity**: When one user action updates canonical data and its audit/version snapshot, or replaces a full relationship set, wrap all writes in one database transaction. Otherwise a failure between statements leaves partial state. Evidence: `server/src/modules/skills/adapters/outbound/persistence/repository.ts:17-30,49-52`.
- [2026-09-27] **Import safety**: Import preview must be the boundary before persistence; archive handling should extract only the markdown core as bytes and never execute archive entries. Preserve imported provenance when saving. Evidence: `client/src/lib/skills-import.ts` and `client/src/app/skills/page.tsx:22-30`.
- [2026-09-27] **Resource bounds**: User-authored markdown and archive-derived content need explicit size and entry limits before parsing, preview, persistence, or prompt assembly. Diff algorithms also need bounded work with a safe fallback for oversized versions. Evidence: `client/src/lib/skills-import.ts` and `client/src/lib/skill-diff.ts`.
- [2026-09-27] **Streaming decompression**: A compressed-size check is not enough for uploaded archives; enforce the expanded-content limit while reading the decompression stream, before materializing the full result. Evidence: `client/src/lib/skills-import.ts:9-33`.
- [2026-09-27] **Accessible control structure**: Do not nest an interactive button inside a label. Use explicit accessible naming (`aria-labelledby`/`aria-label`) with a non-interactive wrapper so browser and assistive-technology behavior remains predictable. Evidence: `client/src/vendor/ui/kit/Checkbox.tsx:16-58`.
