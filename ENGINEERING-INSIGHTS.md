# Engineering insights

Cross-cutting, actionable learnings that apply across modules. Keep entries append-only, specific, and evidence-backed. Module-specific details belong in the relevant module `INSIGHTS.md` file.

- [2026-09-27] **UI correctness**: Model relationship state and activation state separately. A resource can be linked/attached while disabled; controls must render `checked` from the activation field, not from the existence of the relationship. Evidence: `client/src/app/agents/[id]/_components/AgentEditor/_components/SkillsTab/SkillsTab.tsx:18-21`.
- [2026-09-27] **Async UX**: Every user-triggered mutation needs visible pending and error states. Without `Saving…`/disabled handling and an inline error, a failed or slow request is indistinguishable from a frozen button. Evidence: `client/src/app/skills/page.tsx:34`.
- [2026-09-27] **Design verification**: Treat every interactive element shown in a design as an acceptance criterion, not just a visual requirement. For each toggle, save action, tab, and version-row action, verify click behavior, persistence after reload, and the error path. Evidence: `client/src/app/agents/[id]/_components/AgentEditor/_components/SkillsTab/SkillsTab.tsx:21` and `client/src/app/skills/page.tsx:32-34`.
- [2026-09-27] **Version history**: A version list is incomplete when the design exposes comparison behavior. Version history should provide a deterministic diff between adjacent immutable snapshots and must never execute imported or stored markdown. Evidence: `client/src/app/skills/page.tsx:32` and `server/src/modules/skills/adapters/outbound/persistence/repository.ts:39-42`.
- [2026-09-27] **Database integrity**: When one user action updates canonical data and its audit/version snapshot, or replaces a full relationship set, wrap all writes in one database transaction. Otherwise a failure between statements leaves partial state. Evidence: `server/src/modules/skills/adapters/outbound/persistence/repository.ts:17-30,49-52`.
- [2026-09-27] **Import safety**: Import preview must be the boundary before persistence; archive handling should extract only the markdown core as bytes and never execute archive entries. Preserve imported provenance when saving. Evidence: `client/src/lib/skills-import.ts` and `client/src/app/skills/page.tsx:22-30`.
- [2026-09-27] **Resource bounds**: User-authored markdown and archive-derived content need explicit size and entry limits before parsing, preview, persistence, or prompt assembly. Diff algorithms also need bounded work with a safe fallback for oversized versions. Evidence: `client/src/lib/skills-import.ts` and `client/src/lib/skill-diff.ts`.
- [2026-09-27] **Streaming decompression**: A compressed-size check is not enough for uploaded archives; enforce the expanded-content limit while reading the decompression stream, before materializing the full result. Evidence: `client/src/lib/skills-import.ts:9-33`.
- [2026-09-27] **Accessible control structure**: Do not nest an interactive button inside a label. Use explicit accessible naming (`aria-labelledby`/`aria-label`) with a non-interactive wrapper so browser and assistive-technology behavior remains predictable. Evidence: `client/src/vendor/ui/kit/Checkbox.tsx:16-58`.
- [2026-09-28] **CLARIFICATION**: `client/src/vendor/shared` is a symlink to `server/src/vendor/shared` (verified with `ls -la client/src/vendor`), not a byte-identical copy; the 2026-09-17 note saying otherwise is stale. Edit only the server file. Evidence: `client/src/vendor/shared`.
- [2026-10-11] **Codebase Patterns**: Model-generated tours that cite files must be grounded against a path inventory read from the *indexed commit* (`git ls-tree` at the full SHA), not the live worktree or the repo-intel rank list, and that inventory must exclude only credential files (`.env*` except `.env.example`, keys, certs), not directories like `build/` or `vendor/`: `server/src/vendor/shared/**` and `src/build/**` are ordinary source here, and excluding them silently dropped legitimate citations. Evidence: `server/src/modules/onboarding-generator/domain/documents.ts` (`isCredentialPath` vs `isExcludedPath`), `server/test/onboarding-evidence-capture.test.ts`.
- [2026-10-11] **Database integrity**: A shared "latest success" must be a separate pointer row, not derived from request status, and every worker write must be fenced by (request id, attempt token, lease) inside the same transaction as the pointer move; otherwise a superseded or timed-out attempt can publish over a newer result, and a failed regeneration can hide the last good version. Share snapshots must copy content (not reference the version) so retention and regeneration cannot alter them. Evidence: `server/src/modules/onboarding-generator/adapters/outbound/persistence/repository.ts`, `server/test/onboarding-lifecycle.it.test.ts`.
- [2026-10-11] **Security**: Public bearer-token routes need the token kept out of every sink: store only a SHA-256 digest, return generic 404 for malformed/unknown/revoked tokens, send `Cache-Control: no-store` + `Referrer-Policy: no-referrer`, and redact the path in the pino `req` serializer. A fixed demo token is acceptable only in seed data for a fictional tour. Evidence: `server/src/modules/onboarding-generator/adapters/inbound/http/routes.ts`, `server/src/app.ts` (serializers).
- [2026-10-17] **Skill authoring**: A requirement stated only in a skill's `references/*.md` gets dropped by the model; the `pr-self-review` "coverage limitations, even for PASS" rule lived only in `references/finding-policy.md` and passed 0/2 until it was added to SKILL.md's Output contract (0% → 100%, `eval:delta psr-baseline psr-candidate`). Put every output-contract requirement in SKILL.md and use references for detail. Also: a skill that says "grounding ✓ Preserved" without running anything needs an explicit "reserve 'verified' for checks that ran" rule; that practice stayed at 1/2 with n=2 (noise), so do not tune on n=2. (`.claude/skills/pr-self-review/SKILL.md`, `evals/skills/pr-self-review/pr-self-review.cases.ts`)
- [2026-10-17] **Tooling quirk**: `evals/src/config.ts` defaults `EVAL_JUDGE_MODEL` to `openai/gpt-4.1-mini`, which does not exist on the default subscription backend: every judged case fails with "judge returned no JSON ... issue with the selected model". Locally run with `EVAL_JUDGE_MODEL=claude-sonnet-5` (or flip the default temporarily, never commit it); CI sets the judge explicitly in `.github/workflows/evals.yml`, so the committed default must stay the OpenRouter one. (`evals/src/config.ts:10`)
- [2026-10-18] **Tooling quirk**: In a Sonnet 5 session, subagents whose frontmatter pins `model: sonnet` (`implementation-planner`, `implementer`, and likely the reviewers) fail in about 0.4 s with `API Error: 400 To turn thinking off on this model, send "thinking": {"type": "between_tools"}` and 0 tool uses, so nothing is done. Relaunch the same Agent call with `model: "opus"` to override; the retry worked for the planner, implementer, both reviewers, the plan-verifier and the fix agent. (`.claude/agents/*.md`)
- [2026-10-18] **Workflow**: The `implement-plan` skill spawns exactly ONE `implementer` for the whole plan, and its fix loop reacts only to `architecture-reviewer` (`blocking_candidate: yes` or high/critical); `plan-verifier` PARTIALs and `security-reviewer` findings are never auto-fixed. For a plan with ordered slices (server contract first, then client), run the slices manually as separate implementers, then follow steps 2-6 of the skill. Cap fixes explicitly (we used at most 2 iterations and 2 fix agents). (`.claude/skills/implement-plan/SKILL.md:35-55`)
- [2026-10-18] **Decisions**: When two worktrees change shared tables in parallel (multi-agent-review adds `agent_runs.multi_agent_run_id`; export-to-ci writes `agent_runs` with `source='ci'`), the rules are: every aggregation over `agent_runs` filters `source='local'` (estimates, baselines), whoever merges second rebases and regenerates its migration with `pnpm db:generate` (never hand-edit `meta/_journal.json`), and shared files (`modules/index.ts`, `messages/en/*.json`, `query-keys.ts`) only get separate added lines. (`specs/SPEC-2026-10-17-multi-agent-review.md` "Cross-worktree coordination")
- [2026-10-18] **CLARIFICATION** of the 2026-09-17 "byte-identical copies, NOT symlinked" entry: in this repo `client/src/vendor/shared` is a symlink to `server/src/vendor/shared` (`readlink` gives `../../../server/src/vendor/shared`); edit contracts only under `server/src/vendor/shared` and never create a second copy. The typecheck-vs-fixture warning in the neighbouring entry still applies.
