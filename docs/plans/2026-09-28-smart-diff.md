## Objective
Turn the PR "Files changed" tab into a reviewer-ordered diff. Files are grouped by role (core -> tests -> wiring -> docs -> boilerplate) using a pure server-side `classifyFile(path)` and a new no-LLM `GET /pulls/:id/smart-diff` route returning the existing `SmartDiff` contract. The client shows findings from the latest review inline: a "N files with findings" counter on the group header, a dot on the file card, and an inline severity stripe + right-hand label + FindingCard under the finding's `start_line`. A "Smart order | Original order" toggle switches back to GitHub order. Grouping works before any review has run.

## Risks / open questions
- Default visibility vs. the existing "comments hidden by default" behaviour: plan derives the default from "findings exist" (visible) while GitHub comments follow the same switch. If the team wants comments to stay hidden by default even when findings exist, use a separate default per kind but keep one button (needs a decision; not guessed here).
- Stripe/label visibility when the shared toggle is off: plan keeps the stripe + label visible and hides only cards (matches screenshot 1). If "clean diff" should hide everything finding-related, hide the stripe/label too (one-line change in `CodeLine`).
- `package.json` is not in any starter pattern -> `core`, whereas the design mock puts it in Boilerplate. Decide consciously and pin in the table test. Same for nested `dist/`/`build/` (root-anchored per starter list vs `**/dist/**`).
- Original order: `GET /pulls/:id` returns GitHub order only when live GitHub fetch succeeds; on the offline fallback (`persistedDetail`, `pulls.ts:72`) order is `pr_files` physical order (uuid PK, unspecified). This is existing behaviour, not fixed here (fixing needs an ordinal column + migration, out of scope).
- Smart-diff and PR detail can drift (force-push between requests): handled by `ungrouped` in step 6, but a stale smart-diff response is possible until the next refetch.
- Findings with `start_line` on a deleted-only line or `end_line > start_line` anchor only at `start_line` on the new side; multi-line ranges are not stripe-highlighted beyond the start line.
- FindingCard shows its own `file:line` meta link inside the inline card (redundant under a code line). Reuse as is per the task; hiding it would need a small optional prop on FindingCard (not planned).
- `SEV` export path: verify `vendor/ui/index.ts` re-exports `SEV` (only `primitives/index.ts:2` was confirmed).
- Demo video and the PR description (subagent roles, plan-verifier findings) are process deliverables for the human/orchestrator, not code steps.
