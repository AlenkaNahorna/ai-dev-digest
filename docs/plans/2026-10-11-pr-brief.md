## Objective
Add the PR Brief to the Overview tab. `GET /pulls/:id/brief` returns the stored brief or `null`; `POST /pulls/:id/brief` gathers precomputed facts (intent, blast summary and caller files, per-file stats and roles from the git diff with `pr_files` fallback, newest findings, redacted PR text, attached documents), calls the `risk_brief` model exactly once through `completeStructured`, normalizes the answer, and replaces the `pr_brief` row atomically. The card shows the summary, Risk areas and Review focus; a Review focus click opens Files changed scrolled to the file.

## Recommendations
1. **Two extra contract fields.** `missing_inputs: ('intent'|'blast'|'findings'|'documents')[]` and `partial: boolean`, both with defaults. The spec requires the card to name missing data (AC-27) and to say the brief was built from partial data (AC-35) after a reload, and neither can be derived from the stored brief otherwise (findings and documents leave no trace). Trade-off: a contract field beyond the two the task named; both default, so no consumer breaks. Do not store `intent`/`blast` copies in the brief: AC-29 says those blocks read live data.
2. **Cut, do not fail.** Zod bounds on the model output are generous (so `completeStructured` does not re-ask); the precise caps of AC-34 are applied by a pure `normalizeBrief`. This keeps AC-15 true in practice.
3. **Reuse pure helpers across modules instead of copying them** (`classifyFile`, `latestReviewFindings`, `redactSecrets`, `createGetBlastRadius`/`BlastRepository`): they are pure or already the single owner of the rule. The cost is a module-to-module import, which the cruiser allows; if `architecture-reviewer` objects, the fallback is a re-export-free move of the pure helper into `modules/_shared/` (never duplicated).
4. **No server-side generation lock** (user decision, AC-25): the running state is the client mutation's pending state, which disables the Generate and refresh buttons. Nothing is stored. A reload or a second tab during a generation can start another one; both finish and the last atomic write wins.

## Risks / open questions
- **Cross-module imports** in the facts gatherer (`classifyFile`, `latestReviewFindings`, `redactSecrets`, `createGetBlastRadius`/`BlastRepository`) are allowed by the cruiser but discouraged by `onion-architecture`; decided in Recommendations #3, to be confirmed by `architecture-reviewer`.
- **Agent order for the document union** (AC-16a says "agent order"): `agents` has a `createdAt` column; use creation time then id for determinism and state the choice in the gatherer test.
- **Blast for a PR never opened in the UI** is `no_data` (it reads `pr_files`), while files come from git diff, so such a brief lists `blast` as missing even though files exist. This matches the existing blast behavior and the spec; no change planned.
- **No server-side lock** (user decision): a reload or second tab during a generation can start a second model call; accepted, the last atomic write wins.
- **Long synchronous POST.** Generation holds the request until the model answers; set a model `timeoutMs` and let the mutation show pending. If timeouts prove too tight with 30,000 document tokens, tune the constants in `limits.ts`.
- **`setParam` race.** The existing `setParam` copies `search` per call, so two sequential calls (`tab`, then `file`) lose one value; step 10 adds a single-call `setParams`. Verify the severity filter flow still works.
- **Contract additions** (`missing_inputs`, `partial`) go beyond the fields the task named; flagged in Recommendations #1 for the user's veto before step 1.
- **`unavailableHint` copy change** is user-visible text outside the new keys; the spec says names/copy may differ from the task text, so the code wins.
