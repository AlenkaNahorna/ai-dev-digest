## Objective
Show a reviewer what else in the repository a PR can touch, without any model call. A new read-only route `GET /pulls/:id/blast` maps the existing `repoIntel.getBlastRadius(repoId, changedFiles)` result onto the existing `BlastRadius` contract (plus an optional degraded flag/reason). Two consumers read that one route: a "Blast radius" block on the PR Overview tab (summary numbers, collapsible tree of changed symbol -> callers as `file:line` GitHub links, endpoint and cron chips, honest loading/error/degraded/empty states) and the MCP tool `get_blast_radius`, whose visible stub is replaced by a real handler.

2. [server] Pure mapper `domain/map-blast.ts`: `mapBlast(result: BlastResult): BlastRadius`.
   - Files/areas: `server/src/modules/blast/domain/map-blast.ts`. Imports: `import type { BlastResult } from '../../repo-intel/types.js'` (type-only, pure) and `import type { BlastRadius } from '@devdigest/shared'` (alias only). Rules:
     - `changed_symbols` <- `changedSymbols` (`{name,file,kind}`), keep facade order, dedupe `name:file`.
     - `downstream`: one group per distinct `viaSymbol` that has >= 1 caller; group order = order of `changed_symbols` (unknown `viaSymbol`s last, alphabetical); callers `{name: symbol, file, line}` sorted by `rank` desc, then `file`, then `line`; dedupe `file|name|line`. Symbols without callers stay only in `changed_symbols`.
     - Group `endpoints_affected` / `crons_affected`: sorted unique union of `factsByFile[callerFile]` over that group's caller files; `[]` when `factsByFile` is absent.
     - `summary`: `"<S> symbols · <C> callers · <E> endpoints · <K> crons"` with S = `changed_symbols.length`, C = sum of group callers, E / K = unique endpoints / crons across groups (see Reality check for why `impactedEndpoints` is ignored).
     - `degraded: result.degraded === true`; `degraded_reason` only when degraded and `result.reason` present.
     - Known limit (record in `server/INSIGHTS.md` at the end): `viaSymbol` is a bare name, so same-named symbols from different files merge into one group; the contract cannot distinguish them.
   - Skills implementer should apply: `onion-architecture` — pure transformations live in `domain/`, no Drizzle/Fastify/Container/config imports; `typescript-expert` — no `any`, deterministic ordering with explicit comparators, `noUncheckedIndexedAccess` is on (`server/tsconfig.json`); `engineering-insights` — evidence-backed INSIGHTS entry.

## Risks / open questions
- PR files exist in the DB only after `GET /pulls/:id` (see Reality check). Plan keeps blast a pure DB read (precedent: `smartDiffForPull`). Consequence: MCP `get_blast_radius` on a PR never opened in the UI returns degraded `no_data` with a hint to open the PR. Alternative (not in this plan, needs owner decision): when `pr_files` is empty, fetch `container.github().getPullRequest` and call the same persistence as `PullsService.detail`; that adds a network call and a cross-module dependency.
- Caller `line` values come from the repo index (`repo_index_state.lastIndexedSha`), while links pin to the PR `head_sha`. If the index is not at the PR head, `#L<line>` can point at the wrong line. Not verified how/when the clone is advanced for PR heads. Brief says link on `head_sha`; keep, and document the caveat in the card test notes and INSIGHTS.
- Facade caps callers to 20 in total (`MAX_CALLERS_PER_SYMBOL` is applied once to the whole list), so a PR touching many symbols shows few callers for later symbols. Out of scope to change `repo-intel`; the UI/MCP show what the facade returns and the summary counts the shown data.
- `viaSymbol` is a bare name: same-named symbols in different files merge into one downstream group (contract cannot distinguish them).
- `index_partial` is never emitted for blast (partial index returns `degraded: false`), and `flag_off` is reported as `no_data`. The UI and contract still handle all five; manual verification can only reach `no_data`.
- `pr_files` has no status column; deleted/renamed files are passed to the facade as changed files (facade behaviour for non-existent files unverified). No upper bound on the number of files passed (GitHub caps PR file lists; facade query size unverified).
- MCP `tools/list` budget: the new description is longer than the stub text; current token count was not measured here. Measure after editing; trim the description if needed (<= 800 tokens total, each <= 200 chars).
- The MCP HTTP adapter timeout (10 s) vs the ripgrep fallback that reads clone files: a slow degraded call may time out and surface as the generic timeout hint. Unverified; observe during manual run.
- `client/README.md` / `specs/pages.md` do not describe the Overview block; the design screenshot was not available to the planner, so the exact placement (above/below Description) is a default, not a verified requirement.
