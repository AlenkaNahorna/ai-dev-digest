# Server insights

- [2026-09-21] **Codebase Patterns**: PR-list finding badges must aggregate the newest persisted review with SQL counts; page rendering must not invoke reviewer-core or an LLM. Evidence: `server/src/modules/pulls/routes.ts:151`.
- [2026-09-23] **Correctness**: The PR-list FINDINGS column must count only the newest persisted review for each agent; counting every historical run double-counts an agent after reruns, while the detail page remains the full run history. Evidence: `server/src/modules/pulls/routes.ts:125`.
- [2026-09-21] **Recurring Errors & Fixes**: Keep enriched list-only fields nullish in both vendored shared contracts because raw GitHub pull-request fixtures do not provide them. Evidence: `server/src/vendor/shared/contracts/platform.ts:176`.
- [2026-09-27] **Database integrity**: Skill body updates plus `skill_versions` snapshots, and full agent-skill replacement, must execute inside one Drizzle transaction. A delete-then-insert relationship update without a transaction can erase all links on insert failure. Evidence: `server/src/modules/skills/adapters/outbound/persistence/repository.ts:17-30,49-52`.
- [2026-09-27] **Boundary validation**: Collection endpoints must reject duplicate resource IDs and duplicate ordering values at the API boundary, even when the current UI emits normalized data. Evidence: `server/src/modules/skills/adapters/inbound/http/routes.ts:13-22`.
- [2026-09-28] **Codebase Patterns**: Smart Diff counts (`GET /pulls/:id/smart-diff`) use the newest review per agent and never call the LLM; `pr_files` has no ordinal, so GitHub file order must come from `GET /pulls/:id`, not from the smart-diff group order. Evidence: `server/src/modules/reviews/smart-diff/build-smart-diff.ts`, `server/src/modules/reviews/service.ts`.
- [2026-09-29] **Test doubles**: IntentService tests cast hand-built Container and RunLogger fakes to `never`; keep accessed contract fields such as `config.promptLogVerbose` and `correlationId` in sync or failures appear only at runtime. Evidence: `server/test/intent-service.test.ts`, `server/src/modules/reviews/intent/service.ts`.
- [2026-10-04] **Codebase Patterns**: `GET /pulls/:id/blast` maps `repoIntel.getBlastRadius` and computes `summary` and all counts only from the mapped `downstream`, because `impactedEndpoints` is built before the caller cut and can list endpoints no shown caller reaches. `viaSymbol` is a bare name, so same-named symbols from different files merge into one group. Evidence: `server/src/modules/blast/domain/map-blast.ts`.
- [2026-10-04] **Codebase Patterns**: `pr_files` is filled only by `GET /pulls/:id`; blast on a PR never opened in the UI returns degraded `no_data` without calling the facade. The facade's blast path only emits `no_data` (a partial index returns `degraded: false`), and `MAX_CALLERS_PER_SYMBOL` caps the whole caller list, not each symbol. Evidence: `server/src/modules/blast/application/use-cases/get-blast-radius.ts`, `server/src/modules/repo-intel/service.ts`.
- [2026-10-05] **Codebase Patterns**: `GET /pulls/:id/blast` also returns `prior_prs` (earlier PRs of the same repo whose `pr_files` share a path with this PR, newest first, max 5). It is a plain join on `pr_files`, so it only knows PRs whose files were saved (opened in the UI at least once); the field is omitted when empty. Evidence: `server/src/modules/blast/adapters/outbound/persistence/repository.ts`.
- [2026-10-11] **Codebase Patterns**: Project Context documents reach a run only through `container.projectContext.resolveForRun` (facade getter + `ContainerOverrides.projectContext`), and the resolved block is hoisted outside the `try` in `runOneAgent` so `traceFromBuffer` can persist `specs_read`/`specs_detail` for failed and cancelled runs. The application layer cannot import `platform/`, so it throws `ProjectContextError` (forbidden/not_found/invalid) and the HTTP adapter maps it to 403/404/422. Evidence: `server/src/modules/project-context/application/errors.ts`, `server/src/modules/reviews/run-executor.ts`.
- [2026-10-11] **Recurring Errors & Fixes**: `GitClient.readFile` decodes as UTF-8 with U+FFFD substitution and never throws on invalid bytes, so "not valid UTF-8" can only be detected by looking for U+FFFD/NUL in the decoded text (a document that legitimately contains U+FFFD is skipped too). Evidence: `server/src/modules/project-context/domain/doc-text.ts`.
- [2026-10-11] **Recurring Errors & Fixes**: Passing a JS `Date` as a bare parameter inside a Drizzle `sql` template (``sql`${col} >= ${date}` ``) fails under Bun's postgres-js with `ERR_INVALID_ARG_TYPE ... Received an instance of Date` because no column encoder serializes it; use the typed operators (`gte(col, date)`, `lt(col, date)`) so the column's timestamp mapper runs. Evidence: `server/src/modules/onboarding-generator/adapters/outbound/persistence/repository.ts` (budget window, lease expiry).
- [2026-10-11] **Recurring Errors & Fixes**: drizzle-kit names composite/long foreign keys `<table>_<col>_<reftable>_<refcol>_fk`; names over 63 characters are silently truncated by Postgres (a NOTICE at migrate time) and then differ from the snapshot. Declare short explicit `foreignKey({ name })` for self-describing tables with long names. Evidence: `server/src/db/schema/onboarding-generator.ts` (`onboarding_requests_tour_fk`, `onboarding_state_*_fk`).
- [2026-10-11] **Codebase Patterns**: Per-repository index mutations (`indexRepo`, `refreshIndex`, `resyncRepo`) all run through `container.repoIndexLock.withLock` (Postgres session advisory lock on a reserved connection; bounded poll, `pg_advisory_unlock_all` in `finally`, released when the holding backend is terminated). Unit tests that fake the container for `RepoIntelService` must provide a passthrough `repoIndexLock` and `notifyIndexCompleted`. Features subscribe to completed indexes via `container.onIndexCompleted` instead of importing repo-intel internals. Evidence: `server/src/platform/repo-index-lock.ts`, `server/src/modules/repo-intel/service.ts`, `server/test/repo-intel-resync.test.ts`.
- [2026-10-11] **Codebase Patterns**: Read repository files for evidence with `git cat-file blob <full-sha>:<path>` / `git ls-tree -r -l -z --full-tree <sha>` through a spawned process with a streaming byte cap, a minimal env and a timeout; `GitClient.readFile` reads the live worktree and substitutes invalid UTF-8, so it cannot prove which commit a document belongs to. Evidence: `server/src/modules/onboarding-generator/adapters/outbound/providers/git-revision-reader.ts`.
- [2026-10-11] **Codebase Patterns**: `INJECTION_GUARD` in `reviewer-core/src/prompt.ts` is module-private (only `assemblePrompt` appends it), so prompts built outside `assemblePrompt` (PR Brief) carry their own guard sentence next to `wrapUntrusted` blocks; keep the two wordings aligned if the guard changes. The brief facts gatherer reads files from `git diff` then `pr_files` columns directly (not `diffFromPrFiles`, which needs patches), so a PR whose `pr_files` have no patch still yields file stats. Evidence: `server/src/modules/pr-brief/adapters/outbound/providers/brief-prompt.ts`, `facts-gatherer.ts`.
