# Server insights

- [2026-09-21] **Codebase Patterns**: PR-list finding badges must aggregate the newest persisted review with SQL counts; page rendering must not invoke reviewer-core or an LLM. Evidence: `server/src/modules/pulls/routes.ts:151`.
- [2026-09-23] **Correctness**: The PR-list FINDINGS column must count only the newest persisted review for each agent; counting every historical run double-counts an agent after reruns, while the detail page remains the full run history. Evidence: `server/src/modules/pulls/routes.ts:125`.
- [2026-09-21] **Recurring Errors & Fixes**: Keep enriched list-only fields nullish in both vendored shared contracts because raw GitHub pull-request fixtures do not provide them. Evidence: `server/src/vendor/shared/contracts/platform.ts:176`.
- [2026-09-27] **Database integrity**: Skill body updates plus `skill_versions` snapshots, and full agent-skill replacement, must execute inside one Drizzle transaction. A delete-then-insert relationship update without a transaction can erase all links on insert failure. Evidence: `server/src/modules/skills/adapters/outbound/persistence/repository.ts:17-30,49-52`.
- [2026-09-27] **Boundary validation**: Collection endpoints must reject duplicate resource IDs and duplicate ordering values at the API boundary, even when the current UI emits normalized data. Evidence: `server/src/modules/skills/adapters/inbound/http/routes.ts:13-22`.
- [2026-09-28] **Codebase Patterns**: Smart Diff counts (`GET /pulls/:id/smart-diff`) use the newest review per agent and never call the LLM; `pr_files` has no ordinal, so GitHub file order must come from `GET /pulls/:id`, not from the smart-diff group order. Evidence: `server/src/modules/reviews/smart-diff/build-smart-diff.ts`, `server/src/modules/reviews/service.ts`.
- [2026-09-29] **Test doubles**: IntentService tests cast hand-built Container and RunLogger fakes to `never`; keep accessed contract fields such as `config.promptLogVerbose` and `correlationId` in sync or failures appear only at runtime. Evidence: `server/test/intent-service.test.ts`, `server/src/modules/reviews/intent/service.ts`.
- [2026-10-04] **Codebase Patterns**: `GET /pulls/:id/blast` maps `repoIntel.getBlastRadius` and computes `summary` and all counts only from the mapped `downstream`, because `impactedEndpoints` is built before the caller cut and can list endpoints no shown caller reaches. `viaSymbol` is a bare name, so same-named symbols from different files merge into one group. Evidence: `server/src/modules/blast/domain/map-blast.ts`.
- [2026-10-04] **Codebase Patterns**: `pr_files` is filled only by `GET /pulls/:id`; blast on a PR never opened in the UI returns degraded `no_data` without calling the facade. The facade's blast path only emits `no_data` (a partial index returns `degraded: false`), and `MAX_CALLERS_PER_SYMBOL` caps the whole caller list, not each symbol. Evidence: `server/src/modules/blast/application/use-cases/get-blast-radius.ts`, `server/src/modules/repo-intel/service.ts`.
